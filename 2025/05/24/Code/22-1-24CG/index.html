Java三层架构入门指南

什么是三层架构？

三层架构是一种常用的软件设计模式，将应用程序分为三个逻辑层次：

  1. 表示层（Presentation Layer）：用户交互界面
  2. 业务逻辑层（Business Logic Layer）：处理业务规则和逻辑
  3. 数据访问层（Data Access Layer）：负责数据存取操作

这种分层设计使代码更易维护、扩展和测试。

简单三层架构实现示例

下面通过一个用户查询功能演示基本实现（使用内存数据模拟数据库）

文件结构

src
├── entity
│ └── User.java // 实体类
├── dao
│ ├── UserDao.java // 数据访问接口
│ └── UserDaoImpl.java // 数据访问实现
├── service
│ ├── UserService.java // 业务逻辑接口
│ └── UserServiceImpl.java // 业务逻辑实现
└── presentation
└── MainApp.java // 表示层入口

1. 实体类（entity/User.java）

public class User {
    private int id;
    private String name;
    private String email;
    
    // 构造方法
    public User(int id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }
    
    // Getter方法
    public int getId() { return id; }
    public String getName() { return name; }
    public String getEmail() { return email; }
}
2. 数据访问层（dao）
接口定义（UserDao.java）：

java
public interface UserDao {
    User findUserById(int id); // 根据ID查询用户
}
接口实现（UserDaoImpl.java）：

java
import entity.User;
import java.util.HashMap;
import java.util.Map;

public class UserDaoImpl implements UserDao {
    // 模拟数据库
    private static final Map<Integer, User> userDB = new HashMap<>();
    
    static {
        // 初始化测试数据
        userDB.put(1, new User(1, "张三", "zhangsan@example.com"));
        userDB.put(2, new User(2, "李四", "lisi@example.com"));
    }
    
    @Override
    public User findUserById(int id) {
        System.out.println("DAO层：查询用户ID=" + id);
        return userDB.get(id); // 模拟数据库查询
    }
}
3. 业务逻辑层（service）
接口定义（UserService.java）：

java
public interface UserService {
    User getUserInfo(int userId); // 获取用户信息
}
接口实现（UserServiceImpl.java）：

java
import dao.UserDao;
import dao.UserDaoImpl;
import entity.User;

public class UserServiceImpl implements UserService {
    private final UserDao userDao = new UserDaoImpl();
    
    @Override
    public User getUserInfo(int userId) {
        System.out.println("Service层：处理用户信息请求");
        
        // 业务逻辑处理（示例：简单验证）
        if(userId <= 0) {
            throw new IllegalArgumentException("用户ID无效");
        }
        
        // 调用DAO层获取数据
        User user = userDao.findUserById(userId);
        
        // 业务处理（示例：补充信息）
        if(user != null) {
            System.out.println("Service层：验证用户权限");
        }
        return user;
    }
}
4. 表示层（presentation/MainApp.java）
java
import service.UserService;
import service.UserServiceImpl;
import entity.User;

public class MainApp {
    public static void main(String[] args) {
        UserService userService = new UserServiceImpl();
        
        // 模拟用户输入ID=1
        int inputUserId = 1;
        System.out.println("表示层：接收用户请求，ID=" + inputUserId);
        
        // 调用Service层
        User user = userService.getUserInfo(inputUserId);
        
        // 显示结果
        if(user != null) {
            System.out.println("\n查询结果：");
            System.out.println("ID: " + user.getId());
            System.out.println("姓名: " + user.getName());
            System.out.println("邮箱: " + user.getEmail());
        } else {
            System.out.println("用户不存在");
        }
    }
}
执行流程说明
表示层接收用户输入（ID=1）

业务逻辑层处理业务规则（验证ID有效性）

数据访问层执行数据查询操作

结果逐层返回，最终在表示层展示

表示层：接收用户请求，ID=1
Service层：处理用户信息请求
DAO层：查询用户ID=1
Service层：验证用户权限

查询结果：
ID: 1
姓名: 张三
邮箱: zhangsan@example.com
三层架构的优势
解耦合：各层独立变化不影响其他层

复用性：业务逻辑可被多个表示层复用

可维护性：问题定位更快速

分工协作：不同开发者可并行开发不同层

提示：实际项目中常结合Spring框架实现依赖注入，进一步降低层间耦合
