Live2D 模型加载失败，从 model3.json 开始检查

SLLYING2022.07.292 分钟

模型文件、纹理、动作和物理参数依靠入口清单关联。先检查引用关系与大小写，再判断是渲染、版本还是文件缺失。

这是旧站 Live2D 主题的重新整理。接手一个模型时，最值得先看的文件通常是 model3.json，因为它描述了运行时需要加载哪些资源。

先看入口引用

{
  "Version": 3,
  "FileReferences": {
    "Moc": "character.moc3",
    "Textures": ["textures/texture_00.png"],
    "Physics": "character.physics3.json"
  }
}

这是最小结构示例，真实模型可能还有表情、动作、姿态和用户数据。逐项确认相对路径与大小写。在 Windows 上看似正常的引用，部署到区分大小写的环境后可能直接失效。

分开判断资源与渲染问题

先检查网络响应、文件格式和模型版本。请求返回 200 但正文是 SPA 入口 HTML，也会导致解析失败。资源正常后，再检查 Canvas 尺寸、WebGL 上下文、模型缩放与画面坐标，避免把模型在视野外误判成加载失败。

参数改变了，画面为什么没变

表情、动作和物理更新可能在同一帧覆盖同一个参数。调试时暂时只保留一条参数更新链，确认参数 ID、取值范围和应用顺序，再逐项恢复其他效果。
