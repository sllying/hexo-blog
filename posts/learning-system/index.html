给学习工具接入 FSRS：先固定算法输入和本地数据

SLLYING2026.09.083 分钟阅读

复习算法、SQLite、归档与同步一起进入项目时，最容易混淆的是边界。把时间和评分变成明确输入，才能让一次复习可以重放。

在一个学习工具的开发记录里，FSRS 不是直接塞进卡片页面的一段计算。它被放进独立学习引擎，与 SQLite、本地媒体和同步协议分别建立契约。

根据真实实现记录整理。本文保留技术选择与验证方法，不包含学习内容、用户数据或私有仓库名称。

为什么要把时间作为输入

调度结果依赖评分、上一次状态和当前时间。如果函数内部随处读取系统时间，同一条用例可能在不同机器或执行时刻得到不同结果。测试应固定时间、初始卡片和评分序列，再断言调度输出。

type ReviewInput = {
    cardId: string;
    reviewedAt: string;
    rating: "again" | "hard" | "good" | "easy";
};

type ReviewResult = {
    nextDueAt: string;
    algorithmVersion: string;
    nextState: unknown;
};

这是简化契约，不是某个 FSRS 包的直接 API。真实接口还要精确定义状态结构。原任务锁定了算法依赖版本，并使用固定向量约束评分映射；前端若只提供三档评分，更需要明确它们如何映射到算法语义。

复习记录和新状态一起保存

一次复习至少产生事件记录和卡片新状态。两者应在同一个事务中落盘，避免记录写了而到期时间没更新，或到期时间变了却没有历史可以追踪。调度算法版本也应留下，方便升级后解释差异。

数据能读，不代表备份能恢复

实现记录还涉及归档路径、manifest、哈希和压缩比校验。备份验收需要在新目录恢复，并检查数据库和媒体引用是否一致。SQLite 放在独立 Worker 里有助于隔离阻塞，但这个选择本身不自动提供迁移正确性或恢复能力。

原记录能支持这些模块已进入实现与测试，不能据此声称已经有长期用户效果数据。算法集成是否正确，和学习效果是否改善，也是两个分别验证的问题。
