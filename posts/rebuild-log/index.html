重做博客之前，我先承认上一版做错了什么

SLLYING2026.09.082 分钟阅读

我想要的是有角色、有阅读感的个人博客，上一版却堆了信号站术语、重复裁切和空泛文章。这次先把内容和真实素材找回来。

文章目录 0%
  1. 图片数量并不等于视觉内容
  2. 更严重的问题是文章
  3. 以后怎么判断一次改版是否完成

这次重做起于一句直接的反馈：页面不好看，也没有实现原来的需求。回看上一轮，我想要的二次元个人博客，被写成了一座到处都有编号、英文状态和装饰边框的“信号站”。

图片数量并不等于视觉内容

旧版本有多张封面文件，但它们大多来自同一张背景的不同裁切。第一次渲染里，部分文章卡甚至没有用到数据中的 cover 字段。文件存在和读者看到图片，是两件必须分别检查的事。

角色和场景需要真正出现在页面里。裁切应该服务于构图和屏幕比例，不能把一张图切成几份以后，就当作内容变丰富了。

更严重的问题是文章

上一版把“对话脱敏”处理成了删除具体经历，最后只剩原则清单。一篇标着七八分钟的文章，正文却只有几段。它还因为仓库没有聊天导出，就写成没有真实对话可用；实际上本地任务和 Claude Code 记录里有可核实的技术过程。

新整理的复盘保留了真实的问题：代理返回了别的应用、Push 游标跳过其他设备的变更、SQL 转储哈希误判、调度抖动错过当天任务。项目名称和设备信息被替换，但错误、转折和验证边界保留下来。

以后怎么判断一次改版是否完成

先看实际页面，再看实现说明：移动端能不能完整看到标题；封面是否真的加载；进入文章后能不能专心阅读；搜索结果是否对应正文主题；旧链接是否还到得了内容。关于本站的文字也应该说人话，不再用一套虚构的终端术语代替个人表达。

我希望这里像一个长期使用的个人博客：有喜欢的角色，也有值得回来再看一次的技术笔记。
